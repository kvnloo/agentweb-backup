## ENG-2720: enrichment helper LLM calls still ran on the retired gpt-5-chat-2, which is gpt-5.5 (2026-11-05)

**Symptom.** After the extraction default moved to gpt-5.6-luna, three small LLM calls around an enrichment run still named `gpt-5-chat-2`: alias inference and smart-field classification when a list's enrichment config is saved (`enrichmentConfigDeps.ts`, env `CRM_ENRICH_V3_ALIAS_MODEL` / `CRM_ENRICH_V3_CLASSIFY_MODEL`) and the sibling field mapping at the start of a run (`enrichmentSiblingConfigFields.ts`, env `CRM_ENRICH_V3_EXTRACT_MODEL`). `gpt-5-chat-2` was removed from the registry on 2026-08-19 and `LEGACY_MODEL_ALIASES` rewrites it to gpt-5.5, so these ran on the dearest model while the rest of enrichment ran on the cheap default.

**Fix.** `createEnrichmentHelperLLM(userId, envModel?)` (`services/enrichmentMappingLlm.ts`) uses the env override if set, else `resolveModelForUser(userId, 'enrichment')`, the same role the extraction, critic and web-search calls use, so the role default (`CRM_ENRICH_V3_DEFAULT_MODEL` rollback included) and an org's own override cover the whole pipeline. Like the extraction calls it retries an empty 200 (`requireContent`) and the cheap default falls back to gpt-5.5 on a provider error. `CHEAP_DEFAULT_MODEL` / `FALLBACK_MODEL` moved there from `enrichmentV3RealDeps.ts` (same values). All three calls still fail soft (`{}` / field-to-itself mapping) exactly as before.

**Not changed.** The V1 service (`crmEnrichmentService.ts`: `DEFAULT_ENRICH_MODEL` / `DEFAULT_SUGGEST_MODEL`, the admin `crm-enrichment-config` setting) still defaults to `gpt-5-chat-2`, and prod has a stored `crm-enrichment-config` row that pins both to `gpt-5-chat-2`, so changing the code defaults would not change prod. Only `CrmEnrichmentService.suggestEnrichment` (the suggest-fields-from-a-goal button) and the V1 alias/cluster helpers read it. Exhausted `requireContent` retries still do not count in the run-level failure counters. Also a two-line comment fix in `enrichmentBatchBudget.ts` (the unpriced reserve equals gpt-5.5's, it is not above every priced model).

**Cost.** One short call per saved config (alias, classify) and one per run (sibling mapping), not per lead, so the saving is small; it is for consistency and to stop the retired id from ever pinning a call to the dearest model.
