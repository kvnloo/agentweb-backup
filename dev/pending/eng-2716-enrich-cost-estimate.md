## ENG-2716: CRM enrich-v3 pre-run cost estimate + confirmation token (2026-10-28)

Added pure `estimateEnrichmentCost` (calibrated to Opiner 112 leads -> $31.60), `POST /api/crm/lists/:listId/leads/enrich-v3/estimate`, and optional `confirmEstimateToken` check on enrich-v3 (409 on stale token; missing token rejected only when `ENRICH_V3_REQUIRE_COST_CONFIRMATION=true`). Dark until portal confirm dialog ships.

**Reworked 2026-11-02 (ENG-2720, PR #3867):** the quote endpoints (`POST .../enrich-v3/estimate`, `POST .../enrich-v3?mode=estimate`, and the stale-token 409) now return only `{ leadCount, estimatedPercentOfAllowance, withinAllowance, confirmationToken }` (ENG-1212: no dollars, no vendor breakdown); the logic lives in `services/enrichmentQuote.ts`. The expected cost is config-aware (LLM line scales with the saved config's fields and the enrichment model), lead-aware (Apollo only on leads with no usable email) and includes one Enigma fetch when an allowlisted user asks for a card-revenue field; the Opiner 112-lead reference run at the reference config is $13.61 (was $31.60). `withinAllowance` is the conservative admission reserve (`enrichmentBatchBudget.ts`) for that config. The confirmation token is now an HMAC under the server secret and bound to the user (the old unkeyed hash could be brute-forced back into the dollar total); tokens issued before the deploy go stale and the client re-fetches.
