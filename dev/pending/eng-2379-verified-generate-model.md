## ENG-2379: /verified-generate keeps the user-selected model (2026-10-13)

`runVerifiedChat` swapped `session.llmModel` for the report/image/video task-type model whenever it was called without a model, which the interactive `POST /api/agent-mode/verified-generate` always was. The handler now resolves the user's model (request `llmModel`, else the stored one) and passes it, so task defaults apply only when the session has no model. An unavailable explicit pick returns the same 422 `model_unavailable` as `/generate` before any work starts; a retired stored model still falls back to the current default (stored is not explicit). Scheduled, Slack, email, revision, human-eval and result-endpoint callers are unchanged. `GET /api/agent-mode/session/:id` now sends `Cache-Control: no-store`.
