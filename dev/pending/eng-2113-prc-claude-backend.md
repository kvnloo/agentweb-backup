## ENG-2113: a chat turn can run on the user's own Claude plan (PR C, dark) (2026-10-26)

- **What it is.** `/generate` can run ONE interactive chat turn on the session owner's own Claude subscription instead of AgentWeb's models. It is opt-in per request (`fundingChoice: "claude_subscription"`), allow-listed per user (default deny, exact user ids, `*` ignored) and OFF in production (flag off, allow-list empty). Without `fundingChoice` nothing changes for anyone. Merging this does not expose it to any user.
- **Where it runs.** In the MAIN process: `ClaudeCodeBackend` renders one prompt, opens a per-turn tool-bridge run, calls the login host (`turn.run`), maps the bridge ledger to Emma's persisted message shape and returns the same result the worker returns, so the controller persists and answers it as today. The turn never reaches the worker: a plan request that cannot be served is a typed stop (`ClaudeRouteStopError`), never an AgentWeb run.
- **What the plan route skips** (AgentWeb's allowance and policy protect AgentWeb's quota, which the plan route does not use): `checkTokenUsage(TURN_ADMISSION)`, the model-policy resolver, the stored-model rewrite, `assertModelInOwnerPlan`, the work-plan step-model swap, `resolveRunFunding`, and the automatic media / work-plan continuations (they would run on AgentWeb's models). Titles, embeddings and tool APIs stay AgentWeb-funded and attributed (decision of 2026-10-23).
- **Stop.** Every cancel site already calls `generateMarketingResponseWorkerService.cancelSession`; it now also reaches `claudeRunRegistry`, which refuses new bridge calls then aborts the host turn. Shutdown waits for running plan turns and then stops them. A call still executing at Stop is saved into the chat when it finishes.
- **Ledger.** `BridgeCallRecord` gains `answeredContent` (what the model was actually handed, so a withheld approval token never enters history) and `duplicateOfId`. The run token is prefixed `awr_` (a bare base64url token starting with `-`/`_` was refused by the host schema ~1 turn in 32).
- **Known limits (next PRs).** No approval decks (a tool that needs confirmation ends the turn with a plain note; Meta writes cannot be confirmed), nothing persisted mid-turn, no citations, no work-plan retry, tool calls are not grouped per model message (the CLI stream carries no message id), `/verified-generate` ignores `fundingChoice`, usage on the message excludes cache tokens, the exact-model-name work is a separate PR.
- **Verification.** Unit + mutation tests (every guard has a killed mutant), a real-`ToolBridge` backend test, and live scripts on the test instance with the kept login (Haiku only): the real backend, the real host and CLI, and Emma's 98 real tools, real 100k-char prompt and Dev data. Scripts: `loginHost/__tests__/live/claude{TurnPipeline,Backend,EmmaTools}Live.ts`.
