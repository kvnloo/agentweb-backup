# Sandbox Mode — real product, simulated Meta

**Status:** design for approval · 2026-09-12 · supersedes the experience layer of ENG-1870 (PR #2858/#2876)
**Owner:** Harsha · **Executor:** Claude swarm / Harsha-Agent · **Related:** ENG-1870 (Verifying), ENG-1872 (naming/copy gate, Todo), OPS-164 (Ryan take-home, In Progress)

## 1. What we are building (one paragraph)

A reusable **sandbox account mode** for hiring take-homes and customer pilots. The evaluatee logs into the **real customer portal** and uses the **real Emma** with the **real tool surface** — dashboards, campaign pages, creative library, work plans, chat — on an account whose Meta connection is a **simulated ad account** seeded from a frozen, sanitized historical dataset. Reads (campaigns, ads, creatives, insights, pixels, pages) are answered from the dataset; writes (create/update campaign, ad set, creative, ad, image upload, budget, pause, activate) are accepted into per-account simulated state and answered with Meta-shaped success, then are immediately re-readable — so Emma and the UI behave exactly as on a live account. No Meta token exists in the account; real Meta is structurally unreachable. Reviewers open the account through Admin → Access Portal and get an exact activity log of every Meta action the evaluatee took.

The pattern is Stripe test mode: **mode is a property of the credential, not a code branch** — same dashboard, same code paths, a persistent banner, hard object isolation, outbound side effects off by default, seeded versioned data, cheap reset and expiry (docs.stripe.com/sandboxes, /keys, /testing-use-cases).

## 2. Why the current build is wrong (and what to keep)

PR #2858 built a **second mini-product** in the backend: an 81-line server-rendered page (`backend/src/routes/evaluationPage.ts`) that dumps raw case files into `<pre>` blocks, a single-shot Gemini call with no tools or memory (`evaluationService.runEvaluation`), a custom 4-kind toy simulator with `sim_<uuid>` ids and one metrics blob per object (`evaluationSimulation.ts`), and an HTTP allowlist that 403s every real portal route (`middleware/evaluation.ts:20-23`). The evaluatee never touches the product; the screenshot from 2026-09-12 is the direct result.

**Keep (reusable as-is, all in `evaluationStore.ts` / `evaluationPolicy.ts` / `delegateAccessToken.ts`):** the `eval_<uuid>` principal, the policy record (`AW-Evaluations`, key `evaluation/<userId>`), `requireActiveEvaluation` as the single policy read, atomic provision (AW-Users + policy + audit), revoke + credential cleanup + append-only audit, reviewer assignment, the OAuth/API-key policy rechecks that make revocation instant, the `scope:'evaluation'` delegate token, and the admin routes. **Retire:** `evaluationPage.ts`, `runEvaluation` + `generationBudget/remaining/reserve`, `materials` + `artifacts`, `evaluationSimulation.ts`, the candidate-facing actions of the `evaluation_workspace` tool, the HTTP allowlist, the socket refusal, the single-tool restriction. ENG-1870's nine human-written acceptance criteria all remain satisfiable under this design (§10).

## 3. Architecture decision

| | A — Real portal + process-level Graph interceptor + in-house simulator (**recommended**) | B — Real Meta sandbox ad account for writes, in-house reads | C — Grow the `/evaluation` mini-app into a portal replica |
|---|---|---|---|
| Fidelity of experience | Identical product; every code path untouched | Identical product; Meta's real write validation | Permanent drift; tests nothing about real Emma |
| Coverage of Meta callers | All: SDK (axios), `metaApiFetch`, ~30 raw `fetch`, 3 axios, crons — one interceptor keyed on host + sentinel token | Same interceptor still needed for reads (Insights API is unsupported on sandbox accounts) | n/a |
| Isolation / reset | Per account, deterministic, offline, reset = drop overlay | One sandbox per Meta app → candidates share an account; reset = real deletes; token is a real credential | fine |
| Vendor risk | None | Meta removed sandbox accounts for ~1 year (2022–23); Limited tier ≈300 writes/hr with 5-min blocks | none |
| Complexity | Simulator must speak Graph wire format (bounded, enumerated in §6) | Everything in A plus a BM, app, system user, token rotation, namespacing | second frontend forever |
| Verdict | **Build** | Optional later "validation mode" behind the same adapter interface; not now | **Reject** (this is what produced the screenshot) |

Evidence for "one interceptor covers everything": `facebook-nodejs-business-sdk@24.0.1` calls `axios(options)` (`dist/cjs.js:125`); the backend's global `fetch` is undici (`undici ^7.24.0`, `axios ^1.9.0` in `backend/package.json`). Two hooks — an undici global dispatcher and an `https.request`/axios adapter hook — see every request to `graph.facebook.com`. Requests carrying a sandbox sentinel token route to the simulator; everything else passes through untouched.

## 5. The simulated Meta connection (Phase 2 reads, Phase 3 writes)

**Sentinel credential.** `connected_accounts` row: `platform:'meta'`, `config.account_type:'ad_account'`, numeric `ad_account_id`, `access_token:'sbx.<userId>.<random>'`, `token_expires_at` ≥ 90 days out (else `ensureFreshMetaAdAccountToken` calls real `oauth/access_token`), `granted_scopes:['ads_read','ads_management']`, `currency`, `account_status:1`. All four credential resolvers then succeed unchanged, Settings shows "Connected", `list_connected_accounts` lists it.

**Interceptor.** Process-level, installed once at boot. **Spike-proven 2026-09-12** (`sandbox-mode/interceptor-spike.js`, Node 20, 10/10 legs): (1) a `globalThis.fetch` wrapper (not a dispatcher swap — version-proof across Node 20/22/24); (2) an axios **default-adapter** wrapper — `facebook-nodejs-business-sdk` has no nested `node_modules` and shares the backend's single `axios@1.9.0`, so this covers the SDK and the three raw axios sites; (3) an `https.request`/`http.request` hook kept only as a fail-closed backstop that audits any sandbox token reaching a client the first two missed (it also works through `follow-redirects`, but needs a faithful fake socket). Refresh calls carry the token as `fb_exchange_token`, not `access_token` — a separate match rule. Match host `graph.facebook.com` / `graph-video.facebook.com` with **any** `/v\d+\.\d+/` prefix (the SDK pins Graph v24.0; raw fetches use `META_API_VERSION` = v25.0) **and** a sentinel token in query, body, multipart, or `Authorization`. Phase 2 opens with a half-day spike on Atem and the prod EB image confirming the runtime (no `engines` field is pinned in the repo): global `fetch` is undici and the `https` hook sees the SDK's axios calls. Matching requests → `MetaSimulator.handle(userId, method, path, params, body)`. Non-sentinel requests pass through untouched. A sentinel token that ever reaches the network is a bug: fail closed and audit. Never hangs (the SDK path has no timeout).

**Graph-faithful surface** (the enumerated read/write set the product actually uses):
- Nodes/edges: `act_<id>` (+`?fields=`), `/campaigns`, `/adsets`, `/ads`, `/adcreatives`, `/adimages` (POST multipart + base64), `/adspixels`, `/customaudiences`, `/targetingsearch`, `/search?type=adgeolocation`; object nodes `/<id>` GET/POST/DELETE for campaign/adset/ad/creative; `/<campaign>/adsets`, `/<adset>/ads`, `/<adset>/adcreatives`; `/<pixel>/stats?aggregation=event|match_keys`, `/<pixel>/events` (CAPI → recorded, 200), `/<dataset>?fields=event_stats`; `/me`, `/me/adaccounts`, `/me/accounts`, `/me/permissions`, `debug_token`, `oauth/access_token` (fb_exchange → same sentinel, far expiry); `/<page>?fields=instagram_business_account`; `/<business>/owned_pages`; `/<creative>?fields=object_story_id…` and `/<post>?fields=attachments{url}`.
- Insights: synchronous `act_|<node>/insights` with `level`, `fields ⊆ ALLOWED_INSIGHTS_FIELDS`, `breakdowns`, `action_breakdowns`, `date_preset|time_range`, `time_increment`, `filtering`, and the ads-edge field call `insights.time_ranges(...)`; **and** the async report flow (`POST → report_run_id`; `GET /<rid>` → `Job Completed`; `GET /<rid>/insights`). Aggregation: resolve window → un-shift dates → filter → group by level/breakdown/day → sum additive fields and every `actions[].action_type` → derive ctr/cpc/cpm/cpp/frequency/cost_per_* → omit all-zero entities → emit names, `date_start/date_stop`, numbers as **strings**.
- Wire format: `{data:[…],paging:{cursors}}` (single page, no `next`), numeric-string ids ≥ 15 digits with `account_id` on every node, adimages `{images:{<filename>:{hash,url}}}`, Graph error envelope `{error:{message,code,error_subcode,error_user_title,error_user_msg,fbtrace_id}}` with code 100 for validation.
- Time: **read-time date shift** so the dataset's last delivery day is always yesterday UTC (the product computes windows from `new Date()` in at least four places; a compile-time shift ages out of `last_7d` in a week). Shifted fields: insights dates, campaign/adset start/stop/end, created/updated times, pixel `last_fired_time` and stats buckets, audience timestamps. Account `timezone_name:'UTC'`.
- Writes: create → id from a per-account 17-digit monotonic generator; echo written fields **exactly** (the product re-reads and string-compares budgets, bid_strategy, start/end, spend_cap and reports any diff as a loud mismatch); `status` default `PAUSED`; `effective_status` derived from ancestors (`CAMPAIGN_PAUSED`, `ADSET_PAUSED`); new ads `PENDING_REVIEW` for a short simulated review window then `ACTIVE`; DELETE = soft (`DELETED`, dropped from lists); budget/schedule minimums mirror Meta's (the product's own validators already run before the write).
- Creative bytes: simulated `/adimages` writes the bytes (the product downloads the source URL server-side first) to `agentweb-user-files/sandbox/<userId>/adimages/<hash>.jpg` (public-read, already CSP-allowlisted) and returns `image_url`/`thumbnail_url` there; seed creatives are copied from the packet assets at provision; rights-withheld creatives get a generated placeholder carrying the creative name.
- Launch gate (`runMetaTrackingGate`): stays **live**. The simulator answers pixel stats from the dataset, and the gate's destination resolver consults the dataset's declared `landers[{url,pixelIds}]` for sandbox tokens instead of fetching public HTML. A candidate who points an ad at an unmeasured URL is blocked exactly as a real customer would be — that is signal, not a bug.
- Management links: one helper replaces `adsmanager.facebook.com?act=` / `managementUrl` with a portal-internal `/meta-campaigns?campaign=<id>` for sandbox accounts (`routes/meta.ts:892`, `routes/metaV2.ts:272/366/438`, chat copy).
- Fleet crons/monitors (metrics snapshot, token refresh, capability sync, tracking monitor, optimisation/destination/alert sweeps, client health): skip `eval_` accounts at each enumeration via one `isSandboxAccount` helper, with a test per enumerator. (v2: route them to sandbox-scoped sinks so reviewers can watch Emma's monitoring behave.)

**State.** Seed dataset = immutable, versioned, shared across accounts (`dataset/<id>/<version>/<chunk>` items in `AW-Evaluations`, following the `metaAudienceSnapshotStore` chunking precedent). Per-account overlay (created/updated objects, uploaded images, CAPI events, review timers) = one CAS item `evaluation/<userId>/sim` with the existing revision guard; mutations also append to the existing audit rows. No new table, no new bucket. Reset = drop overlay + `sandbox/<userId>/` S3 prefix. Upgrade path if the program scales past a few dozen accounts: a GSI or a dedicated table (data-plane gate then).

## 6. Packet → dataset compiler (Phase 4)

Input is the existing sanitized packet layout on Atem (`/home/harsha/ryan-takehome-setup/CANDIDATE_PACKET`): `performance_daily.csv` (134 ad×day rows: spend, impressions, clicks, inline_link_clicks, reported_leads, reported_complete_registrations, reported_purchases), `settings.csv` (objective/currency/timezone per entity), `creative_index.csv` (ad→creative, availability, format), `source_assets/`, `manifest.csv` (checksums + totals), plus a new `case.yaml` (account name/currency/timezone, page, pixel, landers, display-name map for the anonymized `CAMPAIGN_01`-style ids, targeting summaries, review-window seconds).

`backend/scripts/compile-sandbox-dataset.ts <packet> <case.yaml>` → `SandboxDataset v1` JSON: account, pages, pixels (with daily event stats derived from lead columns), custom audiences, campaigns (`OUTCOME_*` objectives, valid goal/billing/bid combos per `metaConstants.ts`), adsets (targeting objects), adcreatives (`object_story_spec`, `link_url`, `url_tags`, image refs), adimages, ads, `insightsDaily` (actions emitted as both `lead` and `offsite_conversion.fb_pixel_lead`, plus `link_click`, `landing_page_view`, `complete_registration`, `purchase`), `insightsBreakdownDaily` (age/gender, placement, device — allocated deterministically from fixed distributions and **flagged approximate** in metadata), reach/frequency (packet has none: deterministic per-ad frequency in [1.2, 2.4], flagged approximate), assets manifest. Validation: numeric ids only, no real Meta ids/domains/tokens, totals reconcile to `performance_period.csv` and `manifest.csv`, every product validator passes on the seed. `provision --dataset <id>@<version>` loads it; `reset` reseeds it.

## 7. Reviewer experience

Admin → Access Portal opens the **real portal as the candidate** (read and act). Existing admin surfaces already cover chat history (`/api/admin/chat-sessions?userId`), activities, token usage. New: the `review` payload returns the simulator timeline — every Meta read and write in order with arguments and results, the overlay diff versus seed, and uploaded creatives — exportable as a markdown activity log for the scorecards in `INTERNAL/SCORING_*.md`. Reviewer access stays assignment-based (`reviewerUserIds`) and survives candidate revocation.

**Retention.** Revoke today leaves chat sessions, task executions, S3 uploads (Emma's CSV/tool-response artifacts), knowledge-base files, landers and share links in place indefinitely — `cleanupCredentials` sweeps five credential tables only, and admin delete removes just the user row. Add a `purge` lifecycle action for hiring-data retention: after the review window it deletes sessions, executions, the account's S3 prefixes, KB files, landers and share links, and keeps only the policy record and audit trail.

## 10. Acceptance criteria (proposed — human contract, edit before filing)

1. A sandbox account logs into the real customer portal and sees Settings → Connected Accounts "Meta — Connected", Paid Social and Campaign Performance populated for 7/14/30/90-day windows, and the Emma chat working with streaming — with zero requests leaving the process for `graph.facebook.com` (asserted by an egress recorder in tests and by the interceptor audit in prod).
2. `list_meta_ads_campaigns`, `get_meta_ads_metrics`, `call_meta_ads_insights_api` (sync and async), and `/api/meta/ad-performance` return payloads whose shape matches recorded real-account transcripts field-for-field (string metrics, `{data,paging}`, `date_start/date_stop`, `actions[]`), and whose totals reconcile to the packet's `performance_period.csv`.
3. Emma can create a campaign → ad set → creative (with an uploaded/generated image) → ad and activate it; every step returns Meta-shaped success, the objects appear in the next list/insights read and in the portal, `effective_status` reflects ancestors, and the ad-set read-back check passes with no mismatch.
4. The dataset's most recent delivery day is always "yesterday" regardless of when the account is used.
5. Every denied class (connector OAuth, sends, publish/deploy, third-party writes, browser/MCP, scheduled chats) fails closed through the portal, in-process Emma, and external MCP; no real third-party effect is observable in a full unhappy-path run.
6. Fleet sweeps — Meta crons and monitors, activation CRM sync, onboarding loops, renewal cron, domain reachability, admin/partner listings, reliability snapshots — never include a sandbox account (one test per enumerator); no snapshot rows, CRM leads, nudges, oncall emails, alerts, or reliability-telemetry rows are produced by sandbox accounts, and a sandbox account cannot create a public share link.
7. Exhausting the usage cap yields the product's normal usage block; the cap is set by the Sandbox tier row, which must exist in prod settings before provisioning (provision refuses otherwise).
8. Admin → Access Portal opens the sandbox account in the real portal; `review` returns the ordered Meta action timeline and overlay diff; revocation invalidates all sessions/tokens within one request and reviewer access survives it.
9. Reset restores the exact seed (hash-equal) and removes the account's S3 sandbox prefix.
10. ENG-1870's nine criteria remain green under the new contract (mapped test-by-test in the PR).
11. `purge` removes every candidate-generated artifact (sessions, executions, S3 prefixes, KB files, landers, share links) and leaves only the policy record and audit trail.
